# Harness implementation

`src/rah/harness.py::agent_loop` owns the loop. It supplies the system tool descriptions and user prompt, requests exactly one structured decision through llm-proxy, validates JSON and tool arguments, invokes sandbox-manager, appends the actual observation and repeats. A final decision or bounded failure emits one terminal result. Limits are 40 decisions, 300 seconds between decisions, 30 seconds per tool and 120 seconds per provider request; a blocking inference can extend the overall wall time beyond 300 seconds. Cancellation closes the sandbox independently of inference and suppresses late model results.

`sandbox.py` creates one nonroot, network-disabled container per session. `/work` is 16 MiB tmpfs and `/tmp` is 8 MiB tmpfs. Root is read-only, capabilities are dropped, no-new-privileges is set, RAM is 256 MiB without swap, CPU is one core and process count is 64. Only `worker.py` and package initialization enter the tool image. Fixture input is a bounded path-to-base64 mapping; no user archives are extracted. Tools validate relative paths and resolved symlinks. Read/write support text codecs and base64, preserving binary and CRLF fixtures. Collected symlinks/special files are rejected. Shell commands can read the container's operating system but have no host mounts, credentials or network.

The manager's operation map deduplicates request IDs and rejects argument conflicts. Exec is never automatically retried. A transport failure requires querying the operation status before deciding what to do next. Timeout removes the whole sandbox, including descendants. A command's nonzero exit becomes an observation with typed error, allowing the agent to inspect stderr and recover. Session cancellation is terminal; create a new session to continue. All state is in memory and bounded to 128 session records per harness process; restart resets it and the manager removes this project's labeled orphan containers.

`gateway.py` authenticates client tokens and derives session ownership from a token hash. Internal credentials and the ownership header are generated by the gateway; clients cannot override ownership. The manager, harness and proxy require service authentication. No service except gateway is published. HTTP is suitable only within the trusted development boundary; use TLS/tunneling for remote clients.

`GET .../events` returns SSE with monotonic IDs and cursor replay. Streams close after completion or 30 seconds, so reconnect with the last cursor for longer runs. `GET .../trace` retrieves the same sanitized metadata: tool names, exit codes, error classes, usage, model, provider and timing. Prompts, file contents, command arguments, auth headers and provider credentials are omitted. Final answer text and artifacts are returned separately to the owning client. Traces and artifacts are not persisted by services; the BAF runner saves them under ignored `results/`.

`client.py` implements bounded HTTP calls shared by argparse CLI and `gui.py` (Tkinter). `protocol.py` defines the decision format; `contracts/` describes both wire boundaries. The host-side BAF checker compares artifacts without executing collected code on the host.

## Optional local Codex bridge

This adapter reuses an already authenticated Codex CLI without copying or exporting its ChatGPT credentials. Tested CLI baseline: 0.166.0-alpha.6. Start it on the authenticated host in a separate terminal:

```bash
export BRIDGE_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export CODEX_MODEL=gpt-6-luna
uv run rah-codex-bridge --host 0.0.0.0 --port 8091
```

Set these values in ignored `.env` (use the same bridge token as above):

```dotenv
LLM_PROVIDER=bridge
LLM_PROVIDER_URL=http://host.docker.internal:8091/v0/decision
LLM_API_KEY=YOUR_BRIDGE_TOKEN
LLM_MODEL=gpt-6-luna
```

```bash
docker compose up -d --force-recreate llm-proxy
uv run rah-baf --tasks all --repeat 1 --output results/luna.jsonl
```

PowerShell equivalents use `$env:BRIDGE_TOKEN`, `$env:CODEX_MODEL` and `$env:RAH_CLIENT_TOKEN`. Configure the bridge token and client token through environment/file input, avoiding literals in command history. The bridge bind is deliberately explicit: `0.0.0.0` allows Docker to reach the host; allow only trusted local traffic using the host firewall. This is a trusted development inference endpoint, not a production credential service. Do not expose it to the public internet.

Each request invokes `codex exec --ignore-user-config --ephemeral --skip-git-repo-check --sandbox read-only -m gpt-6-luna --json --output-schema SCHEMA -` in a fresh empty cwd. It disables shell_tool, apps, plugins, multi_agent, browser_use, browser_use_external, computer_use, image_generation, view_image and skill_search, and sets `-c web_search=disabled`. Only supplied messages are inference input. The adapter rejects event items beyond reasoning/agent_message, enforces 110 seconds and 6 MiB output, and returns structured next-tool/final data plus CLI usage. The harness performs every actual task tool call inside Docker. The adapter never receives fixtures/checkers directly, never runs the task and never copies Codex authentication into Compose. These controls constrain a trusted development adapter; they do not establish a separate security boundary around the local CLI.

Default Compose remains offline mock. `LLM_PROVIDER=http` supports a full OpenAI-compatible chat-completions URL with JSON-schema responses. Real providers reject replay input before inference. Model access and external provider failures are reported honestly as failed runs; no fallback silently changes the selected model.
